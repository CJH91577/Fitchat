# Fitchat 手机端走查清单（演示版）

> 这份清单是给「人」照着做的，不是给自动化测试跑的。测试只能验证逻辑，验证不了布局——文字溢出、标签碰撞、点击区域过小，只有实际渲染出来看才会发现。
>
> 请用手机尺寸实际点一遍。发现问题就按 **页面 / 现象 / 复现步骤 / 期望行为** 记下来，先别急着改。

## 一、怎么打开

项目就是这个仓库本身（`C:\Users\admin\codex_project\Fitchat`）。在终端进入该目录并启动：

```bash
cd C:\Users\admin\codex_project\Fitchat
npm run dev
```

等它打印出地址后，在浏览器打开 `http://localhost:3000`。

- 依赖已经装好了（`node_modules` 就在这个目录里）。如果哪天提示找不到依赖，先跑一次 `npm install`。
- 如果它提示端口被占用（"port 3000 is already in use"），说明已经有一个在跑了，直接打开 `http://localhost:3000` 即可，不用重复启动。
- 浏览器里模拟手机：按 `F12` 打开开发者工具，点左上角「手机/平板」图标（Toggle device toolbar），把尺寸设为 iPhone 尺寸（390×844，或直接选一个 iPhone 机型）。
- 用真手机看（推荐，这是手机优先的产品）：让手机和电脑连同一个 Wi-Fi，启动 `npm run dev -- --hostname 0.0.0.0`，在电脑上运行 `ipconfig`，找到「无线局域网适配器 WLAN」里的 IPv4 地址（形如 `192.168.x.x`），在手机浏览器打开 `http://<那个IP>:3000`。注意：这会把服务暴露给同一局域网内的其他设备，用完记得停掉服务。

## 二、走查清单

### 全站通用（每个页面都看一遍）

| # | 看什么 | 通过标准 | 什么算坏了 |
|---|---|---|---|
| G1 | 横向滚动条 | 任何页面都不出现左右滚动条 | 出现横向滚动条，或内容超出屏幕右边 |
| G2 | 文字截断 | 没有文字被裁掉或溢出卡片 | 文字被切掉一半、超出圆角卡片、或压到别的字上 |
| G3 | 点击区域 | 所有能点的东西大约不小于 44×44px | 要点好几次才点中，或容易误触旁边的东西 |
| G4 | 底部导航遮挡 | 每个页面最底下的内容完整可见，不被底部导航挡住 | 最后一个卡片/按钮被导航压住，看不到或点不到 |
| G5 | 底部四个导航 | 今日 / 趋势 / 记录 / 我的 都能点开真实页面，且当前页高亮 | 点某个导航没反应、跳错页、或高亮标错 |

G3 重点看这几处（从样式里能看出偏小，请实际用手指/鼠标确认好不好点）：

- 趋势页「显示体重表格」「显示达标表格」两个小字链接——没有留点击余量，可点高度只有文字那一行。
- 记录运动页每行最右边的「−」删除按钮——当前约 32×32px。
- 底部导航除中间「记录」外的三项——垂直方向留白较小，接近 44px 下限。

### 深浅色模式

| # | 看什么 | 通过标准 | 什么算坏了 |
|---|---|---|---|
| C1 | 浅色模式 | 青、黄两个圆环的颜色比较浅（这是已知的），但每个圆环旁边都有文字标签，且标签清晰可读 | 标签看不清，或认不出圆环是哪个指标 |

## 三、演示数据里看不到的两个状态（诚实说明）

以下两个状态在当前的演示数据里**不会出现**，无法靠肉眼在 app 里看到，目前只由单元测试覆盖：

1. **圆环恰好 100%**：今天四个环分别是 1600/1800、480/500、80/120、197/220，没有一个恰好等于目标。只有当值恰好等于目标时，圆环的圆头线帽会在 12 点方向重叠，产生一个小的凸起——这个潜在外观问题当前演示数据触发不了。
2. **图例的「超出」标记**：只有某天摄入超过目标时，圆环图例才会在第二行显示「超出」。今天没有超标，首页也只展示今天，所以这个标记在 app 里看不到（昨天的数据是超标的，但首页不展示昨天）。

如果之后要人工确认这两个状态，需要程序员临时把 `lib/data/mock.ts` 里今天的数值改成恰好等于或超过目标，看完再改回来。

## 四、已知限制：demo 与真实产品的差距

务必读一遍，别把演示当成品：

- **所有数据都是假的**：饮食、运动、体重、达标率全是写死的演示数据，不落库、不持久化，刷新页面就恢复原样。
- **没有登录与权限**：登录页只是界面，任何页面都可以直接打开，没有真正的注册、邀请码校验或会话。
- **「保存」「解析」没有真实副作用**：解析返回的是预设的假结果，保存不会真的写入任何东西。
- **没有接入 AI**：界面上的「AI 估算」标签是写死的，没有接 DeepSeek 或任何大模型。
- **目标热量是写死的数字**：1800 千卡等目标是写死的，没有实现真实的目标计算。
- **没有错误监控**：没有接入任何日志、监控或崩溃上报。
- **「今天」是写死的 2026-09-22**：演示把「今天」固定在这一天（含星期），所以日期栏、月历高亮、训练计划的「今天」都以它为准，不是真实的系统日期。
- **图表是手绘的 SVG**：不是图表库，只有演示需要的固定形态，不响应真实数据范围、不缩放。
